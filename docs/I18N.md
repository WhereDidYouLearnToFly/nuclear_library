# Internationalization

ISOTOPEDIA supports 4 languages: **English, French, Russian, Ukrainian**.

---

## Language detection

### Blog pages (`/en/`, `/fr/`, `/ru/`, `/ua/`)

Language comes from the URL path:
```
/en/about.html  → en
/ru/index.html  → ru
```

`nav.js` uses: `path.match(/^\/(en|fr|ru|ua)\//)`.

Language switcher swaps the path prefix:
```
/en/about.html  ←→  /fr/about.html  ←→  /ru/about.html  ←→  /ua/about.html
```

Each language has its own copy of every blog page (en/, fr/, ru/, ua/).

### Tool pages (`/table/`, `/powerplants/`, `/detonations/`, `/incidents/`)

Language comes from the `?lang=` query param (default `en`):
```
/detonations/index.html          → en (default)
/detonations/index.html?lang=ru  → ru
```

Language switcher updates the param in place. The tool page loads once and
re-renders its content based on the param — no separate per-language file needed.

---

## Translation pattern in tool pages

Every tool page has a `TR` object directly in the inline `<script>`:

```js
const LANG = new URLSearchParams(location.search).get('lang') || 'en';

const TR = {
  en: { title: 'NUCLEAR INCIDENTS', shown: 'incidents shown', ... },
  fr: { title: 'INCIDENTS NUCLÉAIRES', shown: 'incidents affichés', ... },
  ru: { title: 'ЯДЕРНЫЕ ИНЦИДЕНТЫ', shown: 'инцидентов показано', ... },
  ua: { title: 'ЯДЕРНІ ІНЦИДЕНТИ', shown: 'інцидентів показано', ... },
};

function t(k) { return (TR[LANG] || TR.en)[k] || TR.en[k] || k; }
```

`t(k)` falls back to English if a key is missing in the current language.

## Translating geographic names

Site names and notable tags are **not keys** — they're arbitrary English strings from
`data.js`. These use lookup objects in the inline script:

```js
const SITE_NAMES = {
  // NO 'en' key — English names come directly from data.js
  fr: { "Chernobyl NPP": "Centrale de Tchernobyl", ... },
  ru: { "Chernobyl NPP": "Чернобыльская АЭС", ... },
  ua: { "Chernobyl NPP": "Чорнобильська АЕС", ... },
};

const translatedSite = (SITE_NAMES[LANG] || {})[englishName] || englishName;
```

`detonations/index.html` also has `NOTABLE_TRANS` for the same pattern with notable tags.

## nav.js translation keys

`assets/js/nav.js` holds its own `TR` object for navigation text:

```js
const TR = {
  en: { home: 'HOME', about: 'ABOUT', table: 'NUCLIDE TABLE',
        plants: 'POWER PLANT MAP', detonations: 'DETONATIONS MAP',
        incidents: 'INCIDENTS MAP', experiments: 'EXPERIMENTS',
        footer: 'NUCLEAR PHYSICS EDUCATIONAL TERMINAL', about_link: 'ABOUT' },
  fr: { ... },
  ru: { ... },
  ua: { ... },
};
```

When adding a new nav entry, add the key to **all 4 languages** in this object.

---

## Blog page translations

Blog pages (articles, about, index) are fully translated by having separate files:
```
en/about.html  ← English content
fr/about.html  ← French content
ru/about.html  ← Russian content
ua/about.html  ← Ukrainian content
```

The pages are independent; there is no shared translation system for blog content.
Only `nav.js` is shared (it reads the language from the path).

---

## Ukrainian note

The ISO 639-1 code for Ukrainian is `uk`, but the URL path uses `ua` for consistency
with the domain/folder naming. `nav.js` corrects this when setting `document.documentElement.lang`:

```js
document.documentElement.lang = LANG === 'ua' ? 'uk' : LANG;
```

## Adding a new language

1. Create `/<lang>/` folder with `index.html`, `about.html`
2. Add the language to `nav.js`:
   - Add to `pathLangMatch` regex: `/^\/(en|fr|ru|ua|XX)\//`
   - Add `XX` to the `langSwitcher` array: `['en', 'fr', 'ua', 'ru', 'XX']`
   - Add full TR entry for all nav keys
3. Add TR entries to every tool page's inline `TR` object (4 pages)
4. Add SITE_NAMES entries to detonations and incidents
5. Add `country_XX` keys to tool page TR objects for new country codes
